# BUNKER audit package

Everything an external auditor needs to scope, reproduce and start. This
directory is maintained alongside the code; CI fails if the invariants it
lists stop being tested (`scripts/audit-package-check.mjs`) or if the security
documents stop stating what the code does (`scripts/doc-drift-check.mjs`).

**Status: no independent audit has been performed.** This package exists so
that one can start without a discovery phase. When a report is delivered it is
linked from `SECURITY.md` and copied to `audit/reports/`.

## Scope

| component | path | size | language |
|---|---|---|---|
| shielded pool | `contracts/contracts/ShieldedPool.sol` | ~430 lines (tree, verifier dispatch, pools, shares, turnstile, ASP, exit hook, guardian) | Solidity 0.8.28 |
| launchpad | `contracts/contracts/Launchpad.sol`, `LaunchToken.sol` | ~600 lines (curve, exit hook, fee policy, harvest, graduation, PancakeSwap migration) | Solidity |
| verifiers | `contracts/contracts/verifiers/*.sol` | generated by snarkjs from the zkeys; checked for drift in CI | Solidity |
| circuits | `circuits/src/*.circom` | `transact2x2` 33,515 constraints, `transact4x2` 64,860 | circom 2 |
| SDK (key derivation, note encryption, witness building, call builders) | `sdk/src` | ~2,100 lines | TypeScript |
| relayer | `relayer/src` | ~600 lines | TypeScript |

Out of scope unless agreed: the Next.js app UI (`app/`) beyond its use of
the SDK, the indexer (`indexer/`, a read-only cache; the app verifies every
note it returns), the agents (`agents/`, they hold only the four vote keys and
the treasury), Fly.io deployment config.

## Priorities

1. **Circuits** (`circuits/src/transact.circom`, `keys.circom`, `note.circom`).
   Soundness of the balance equation, nullifier derivation, Merkle membership,
   ASP membership, output address checks. The constraint system is the only
   thing standing between a bug and a full drain up to the turnstile.
2. **`ShieldedPool.transact`**: public input binding (`extDataHash` covers
   everything that moves funds), root lookup, nullifier set, turnstile, share
   math, ERC-20 delivery check, exit hook and reentrancy.
3. **Key derivation and note encryption** (`sdk/src/keys.ts`,
   `encryption.ts`): a wallet-signature-derived seed, scalar truncation to 250
   bits, ChaCha20-Poly1305 with an ephemeral Baby Jubjub key.
4. **Launchpad** (`Launchpad.sol`, SPEC §13, `SECURITY.md` §9–§10): the
   pool-only `onExit`, curve arithmetic and the reserve/fee split, the claim-key
   reserve, the capped last buy, the graduation freeze, the fee-policy roll
   (`rollPure`), and `migrate` (whole balances to `addLiquidityETH`, LP to
   `0xdead`). The pool bounds the damage to what one user just unshielded;
   confirm that bound holds and that nothing in the launchpad can reach pool
   funds.
5. **Relayer**: fee logic, simulation-before-submit, no ability to redirect
   funds (it should be impossible by construction; confirm).

## Reproducing the build

```bash
git clone https://github.com/imadegoodstuff/scash && cd scash
npm ci
npm run -w circuits build && node circuits/scripts/setup-dev.mjs
npm run -w contracts verifiers && git diff --exit-code contracts/contracts/verifiers   # verifiers derived from source must match the committed ones
npm run -w contracts build && git diff --exit-code sdk/src/abi                           # ABIs in the SDK must match
npm test                                                                                 # contracts, sdk, relayer, indexer, agents
npm run -w circuits test                                                                 # adversarial witnesses
npm run e2e                                                                              # whole protocol on a Hardhat node
```

Toolchain versions are pinned in `package-lock.json`, `circuits/package.json`
(circom2, snarkjs) and `contracts/hardhat.config.cjs` (solc 0.8.28, viaIR,
cancun). Deployed addresses are in `contracts/deployments/56.json`; sources are
verified on BscScan (`npm run -w contracts verify:bsc`).

## Documents

- `THREAT_MODEL.md`: assets, actors, trust assumptions, what an attacker can
  and cannot do by design.
- `INVARIANTS.md`: every property the system relies on, where it is enforced,
  and which test exercises it. The list is machine-checked against the test
  files.
- `TEST_MATRIX.md`: what each test suite covers and, more importantly, what
  none of them covers.
- `KNOWN_ISSUES.md`: accepted risks and open items, with the reasoning, so an
  auditor does not spend time rediscovering them.
- `../SPEC.md`: the protocol. `../SECURITY.md`: the current "not done" list.

## Contact

Open a private report through GitHub Security Advisories on the repository
for anything exploitable. Scoping questions and findings that are not
exploitable can go in a regular issue. Engagement terms (fixed scope, fixed
duration, report published in full in `audit/reports/` after fixes) are the
default offer.
